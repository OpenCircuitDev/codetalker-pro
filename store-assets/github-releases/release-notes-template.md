# GitHub Releases — release notes template

This is the canonical body for the GitHub Release tied to each `vX.Y.Z`
git tag. The content is auto-generated by `scripts/release.sh` from
`CHANGELOG.md`; this file is the template the script renders.

## Body skeleton

```markdown
# codetalker companion {version}

{short headline — 1 line}

## What's new

{bullet list pulled from CHANGELOG.md ## [{version}] section}

## Install

- **Google Play:** {playstore-url}  (after the Play track promotes the
  internal build to closed alpha or higher)
- **XREAL Store:** {xreal-url}  (after XREAL Store accepts the build)
- **APK direct download:** see assets below. Verify the SHA-256 against
  the value printed in `app-release.aab.sha256`.

## Verifying the build

```bash
# Confirm the APK is signed with the production keystore.
apksigner verify --verbose app-release.apk

# Compare the SHA-256.
sha256sum app-release.apk
```

The expected SHA-256 fingerprint of the production signing certificate
is published in `docs/DEVELOPER-GUIDE.md` § "Key rotation".

## Known issues

{anything filed in the issues tracker that's deferred to the next
release}

## Full changelog

See [CHANGELOG.md](./CHANGELOG.md).
```

## Asset manifest

Every GitHub Release attaches:

- `app-release.aab` — Play / XREAL upload bundle.
- `app-release.apk` — universal APK for sideload.
- `app-release.apk.sha256`, `app-release.aab.sha256` — checksums.
- `release-notes.md` — the rendered body of the release.

The CI workflow (`.github/workflows/release.yml`) attaches all four on
tag push.
